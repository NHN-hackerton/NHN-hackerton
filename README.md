## 📌 Top Dog Detective는 이런 게임이에요

### 🔥 함구령 뚫기 — 코어 루프

**같은 키워드라도, 어떻게 말하느냐에 따라 결과가 달라집니다.**

- 탐색을 통해 획득한 **키워드 카드**와 **프레이밍 카드**를 조합해 문장을 완성합니다.

- 조직원과의 대화는 **LLM이 실시간으로 판정**하며, 같은 키워드라도 **프레이밍과 활용한 정보**에 따라 결과가 달라집니다.

- 플레이어가 직접 만든 문장을 AI가 이해하고, 조직원의 **심리와 대화 결과를 실시간으로 결정**하는 것이 이 게임의 핵심 플레이입니다.

<br>

### 🔥 정보 흘리기 · 대질 — 반전 메커닉

**얻은 정보가 또 다른 설득의 무기가 됩니다.**

- 측근급 조직원은 단순한 설득만으로는 정보를 말하지 않습니다.

- 다른 조직원에게 얻은 정보를 활용하거나 **대질을 통해 모순을 드러내야만** 함구령을 무너뜨릴 수 있습니다.

- 탐색과 추리가 함께 요구되어 더욱 전략적인 플레이가 가능합니다.

<br>

### 🔥 하이브리드 판정 — AI + 코드

**AI는 대화를 이해하고, 코드는 게임을 관리합니다.**

- 문장이 상대의 약점을 찔렀는지, 함구령을 무너뜨렸는지, 정체를 의심할 만한 발언이었는지는 **LLM이 판정**합니다.

- 반면 **친밀도, 의심도, 게임 진행 등 모든 수치 계산은 게임 로직이 담당**하여 안정적이고 일관된 플레이 경험을 제공합니다.

## 🔗 Git Convention

### 📌 GitHub Flow

| 브랜치 | 설명 |
| --- | --- |
| **master** | 배포·제출 기준 브랜치. 항상 안정 버전만 유지 (별도 develop 없음) |
| `feat/` | 새 기능 개발 브랜치. ex. `feat/llm-proxy` |
| `hotfix/` | 배포 중인 master의 긴급 버그 수정 브랜치. ex. `hotfix/proxy-auth` |
| `chore/` | 기능·버그와 무관한 잡무성 작업 브랜치 (설정 변경 등). ex. `chore/coderabbit-config` |

<br/>

### ✨ 작업 Flow

- `master` 브랜치에서 새로운 브랜치 생성
- 작업 완료 후 커밋 컨벤션에 맞게 커밋 (기능 단위로 분리)
- PR 생성
- 코드 리뷰(CodeRabbit + 팀원) 후 `master` 브랜치로 병합
  - 최소 1명(또는 CodeRabbit) 리뷰 확인 후 병합

<br/>

### 🌿 Branch Naming Convention

- **구조**: `브랜치종류/기능설명`  ex. `feat/llm-proxy-구현`
- **구분자**: 하이픈(`-`) 사용

| Prefix     | 의미                   | 예시                     |
| ---------- | ---------------------- | ------------------------ |
| `init`     | 초기 프로젝트 세팅     | `init/project-setup`     |
| `feat`     | 새로운 기능 추가       | `feat/llm-proxy`         |
| `fix`      | 버그 수정              | `fix/proxy-token-leak`   |
| `docs`     | 문서 변경              | `docs/update-readme`     |
| `style`    | UI 수정                | `style/main-page-ui`     |
| `refactor` | 코드 리팩토링          | `refactor/battle-session`|
| `test`     | 테스트 코드 관련       | `test/dialogue-judge`    |
| `chore`    | 설정 파일 변경         | `chore/coderabbit-config`|
| `hotfix`   | 긴급한 버그 수정       | `hotfix/proxy-down`      |
| `deploy`   | 배포 관련 작업         | `deploy/vercel`          |

<br/>

### 🔥 Commit Message Convention

커밋 유형은 영어 소문자로 작성

- **구조**: `prefix: 상세설명`  ex. `feat: LLM 프록시(Vercel) 구현`

| Prefix     | 설명               |
| ---------- | ------------------ |
| `init`     | 초기 프로젝트 세팅 |
| `feat`     | 새로운 기능 추가   |
| `fix`      | 버그 수정          |
| `docs`     | 문서 변경          |
| `style`    | UI 수정            |
| `refactor` | 코드 리팩토링      |
| `test`     | 테스트 코드 관련   |
| `chore`    | 설정 파일 변경     |
| `hotfix`   | 긴급한 버그 수정   |
| `deploy`   | 배포 관련 작업     |
