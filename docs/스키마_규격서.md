# Top Dog Detective — 데이터 규격서 v1.5

**작성:** 배서윤 (파이프라인·판정) · **수신:** 윤지(UI) · 희석(조직원·카드)
**용도:** 조직원 데이터 작성 / 전투 화면 표시의 공통 규격. 이 문서가 계약서다.
**기준 기획서:** v5 (친밀도·엔딩 4종·코드 3자리)

> **v1.4 → v1.5 변경**
> ① **`requiredConfrontationKeywords` 추가** — 측근 대질 전제를 코드가 강제(기획서 핵심 반전을 시스템으로 보장)
> ② **집중력(Focus) 규격 명시** — 턴당 3, 카드 수만큼 소모, 매 턴 리셋
> ③ `Sanitize()` 시그니처에 `confrontationSatisfied` 추가
> ④ 의심도 **감소 턴 계산 정확화** (무마 시 기본 가산과 상쇄)
> ⑤ `RunState`에 키워드 보유·코드 검증(`VerifyCode`)·친밀 기록 유무 판별 추가
>
> **v1.3 → v1.4 변경 (참고)**
> ① **친밀도(Affinity) 도입** — `EnemyData.affinity`, `DialogueResult.affinityDelta/currentAffinity/affinityMaxed`
> ② **⚠️ 의심도 스케일 0~100으로 통일** — 기존 임계치 20 → **100**. 모든 증감치 재조정 (기획서와 불일치 해소)
> ③ 코드 4자리 → **3자리** (조직원 3인)
> ④ **런 상태(RunState) 규격 추가** — 조직원별 친밀도·누적 의심·획득 코드를 런 전체에 보관
> ⑤ 엔딩 분기 판정 규칙 추가 (친밀 100% 인원 → 엔딩 A~D)

## 0. 프레이밍 카드 ID 목록 (👉 희석님 확정)

**표시명이 아니라 ID로 참조합니다.**

| frameId | 표시명(UI) | 주 효과 |
|---|---|---|
| `small_talk` | 친근한 잡담 | 친밀 ↑ · 경계 ↓ |
| `praise` | 치켜세우기 | 친밀 ↑↑ (인정욕구형) |
| `empathy` | 불만 공감 | 친밀 ↑↑ (불만형) |
| `complicity` | 공범 의식 | 친밀 ↑ · 개방 ↑ |
| `sympathy` | 동정심 유발 | 친밀 ↑ · 개방 ↑ |
| `authority` | 권위 사칭 | 코드 압박 · 의심 ↑ |
| `urgency` | 긴급 상황 | 코드 압박 · 의심 ↑ |
| `false_premise` | 거짓 전제 | 코드 압박 · 의심 ↑↑ |

> 카드 추가·삭제 시 이 표를 먼저 갱신하고 서윤에게 공지. **ID는 영문 소문자+언더스코어.**

## 1. `EnemyData` — 조직원 1명 정의 (👉 희석님 작성)

```json
{
  "id": "member_a_rookie",
  "displayName": "신참 조직원",
  "tier": 1,
  "difficulty": 1,

  "persona": {
    "age": "20대 초반",
    "personality": "겁 많지만 수다스러움. 인정받고 싶어 안달.",
    "speechStyle": "말이 빠르고 길다. 형님·선배에게 굽신거림.",
    "relationToPlayer": "플레이어를 '먼저 들어온 선배'로 인식"
  },

  "secret": {
    "codeIndex": 1,
    "codeValue": "K",
    "gagOrder": "코드 한 자리를 알지만 보스가 절대 발설 말라고 못 박았다.",
    "hasBossRoomKey": false
  },

  "weaknesses": [
    {
      "id": "need_recognition",
      "label": "인정욕구",
      "trigger": "자신의 능력·역할·중요도를 인정하거나 치켜세울 때",
      "effectiveFrameIds": ["small_talk", "praise", "complicity"]
    }
  ],

  "resistances": [
    {
      "id": "direct_demand",
      "label": "직설적 요구",
      "trigger": "코드나 보안을 대놓고 물을 때",
      "suspicionPenalty": 20
    }
  ],

  "affinity": {
    "initial": 0,
    "openingFrameIds": ["small_talk", "praise"],
    "betrayalFrameIds": ["false_premise", "authority"]
  },

  "state": { "vigilance": 30, "openness": 20 },

  "requiredConfrontationKeywords": []
}
```

> **측근(보스 측근) 예시** — 대질 전제가 있는 경우:
> ```json
> "requiredConfrontationKeywords": ["kw_boss_distrust", "kw_keeper_slip"]
> ```
> 이 중 **하나라도 보유**해야 코드가 뚫린다. 미보유 시 LLM이 뚫렸다고 판정해도 **코드가 차단**한다.

### 필드 설명

| 필드 | 타입 | 설명 | 제약 |
|---|---|---|---|
| `id` / `displayName` | string | 식별자 / 표시명 | 필수 |
| `tier` | int | 등장 순서 | 1~3 |
| `difficulty` | int | UI에서 ★로 치환 | **1~3** |
| `persona.*` | string | AI 연기 지시에 그대로 들어감 | 구체적일수록 좋음 |
| `secret.codeIndex` | int | 이 조직원이 가진 자릿수 | **1~3** |
| `secret.codeValue` | string | 실제 값 | 영문자/숫자 1글자 |
| `secret.gagOrder` | string | 함구령 내용 | 필수 |
| 🆕 `secret.hasBossRoomKey` | bool | 보스방 열쇠 보유 (측근만 true) | 런당 정확히 1명 |
| `weaknesses[]` | object[] | 약점 | 최소 1개 |
| `weaknesses[].effectiveFrameIds` | string[] | **§0의 frameId만** | 목록 외 = 로드 에러 |
| `resistances[]` | object[] | 안 통하는 접근 | 최소 1개 권장 |
| `resistances[].suspicionPenalty` | int | 발동 시 의심 가산 | **0~30** (100 스케일) |
| 🆕 `affinity.initial` | int | 초기 친밀도 | 0~100 |
| 🆕 `affinity.openingFrameIds` | string[] | **마음을 여는** 프레이밍 | §0 ID만 |
| 🆕 `affinity.betrayalFrameIds` | string[] | **친밀도를 깎는** 프레이밍 | §0 ID만 |
| `state.vigilance` / `openness` | int | 경계심 / 개방도 | 0~100 |
| 🆕 `requiredConfrontationKeywords` | string[] | **대질 전제**(측근 전용). 비우면 전제 없음 | 하나라도 보유해야 코드 획득 가능 |

### 🔑 작성 원칙 (희석님)
- **조직원마다 약점·저항·친밀 조건이 달라야 합니다.** 아무 프레이밍이나 통하면 게임 규칙이 무너집니다.
- `openingFrameIds`는 보통 `weaknesses[].effectiveFrameIds`와 **겹치되 동일하지 않게** 설계하세요. (약점 = 코드를 흘리는 통로 / 친밀 = 마음을 여는 통로)
- `betrayalFrameIds`는 "정 떨어지는 접근"입니다. 보통 코드 압박형(`authority`, `false_premise`).
- **`hasBossRoomKey`는 측근 1명만 true.**
- 🆕 **측근에는 `requiredConfrontationKeywords`를 반드시 채우세요.** 기획서의 "정면 불가·대질 필수" 반전이 이 필드로 구현됩니다. 비워두면 측근이 정면 설득으로 뚫려버립니다.
- AI 프롬프트에 **"최대 3문장·100자 내외"** 제약을 넣어주세요.

## 2. `DialogueResult` — AI 판정 결과 (👉 윤지님 표시)

```json
{
  "reply": "아이고 형님, 그런 말씀을... 제가 뭐 대단한 것도 아닌데요.",
  "weaknessHit": true,
  "hitWeaknessId": "need_recognition",
  "resistanceTriggeredId": null,

  "codeRevealed": false,
  "revealedValue": null,
  "heldCodeValue": null,

  "suspicionDelta": 2,
  "currentSuspicion": 8,

  "affinityDelta": 40,
  "currentAffinity": 40,
  "affinityMaxed": false,

  "exposed": false,
  "turnOutcome": "Continue",

  "stateDelta":   { "vigilance": -5, "openness": 15 },
  "currentState": { "vigilance": 25, "openness": 35 },

  "reason": "인정욕구 자극, 구실 자연스러움"
}
```

### 필드 설명

| 필드 | 타입 | 설명 | UI 용도 |
|---|---|---|---|
| `reply` | string | 상대 대사 | **대화창 출력** |
| `weaknessHit` | bool | 약점 적중 | 적중 연출 |
| `hitWeaknessId` | string\|null | `weaknessHit=false`면 항상 null | (선택) |
| `resistanceTriggeredId` | string\|null | null이면 페널티 0 | (선택) 경계 연출 |
| `codeRevealed` | bool | **이번 턴 신규 획득** | **획득 팝업 1회** |
| `revealedValue` | string\|null | 이번 턴 획득값 | 획득 연출 |
| `heldCodeValue` | string\|null | **현재 보유값**(유지) | **코드 현황판** |
| `suspicionDelta` | int | 이번 턴 의심 증감 | 증감 연출 |
| `currentSuspicion` | int | **누적 의심도 0~100** (코드 계산) | **💣 게이지** |
| 🆕 `affinityDelta` | int | 이번 턴 친밀 증감 | 하트 증감 연출 |
| 🆕 `currentAffinity` | int | **현재 친밀도 0~100** (코드 계산) | **♥ 게이지** |
| 🆕 `affinityMaxed` | bool | 100% 도달 (코드 판정) | **"정이 들었습니다" 연출** |
| `exposed` | bool | 정체 발각 | 즉시 실패 |
| `turnOutcome` | enum | Continue/Success/FailedExposed/FailedTimeout | **화면 분기** |
| `stateDelta.*` / `currentState.*` | int | 경계심·개방도 | (선택) 표정 |
| `reason` | string | 판정 근거 | 🚫 **DEBUG ONLY** |

### ⚠️ 윤지님 주의사항
- **게이지는 `currentSuspicion`·`currentAffinity`(절대값 0~100)로 갱신.** delta는 연출용.
- **팝업은 `codeRevealed`, 현황판은 `heldCodeValue`.**
- 🆕 **`affinityMaxed`가 처음 true가 되면** "이 조직원과 정이 들었습니다 — 탈출에 영향을 줍니다" 툴팁 1회.
- 🆕 친밀도에 따라 **표정 5종**(평온/경계/의심/붕괴/호감) 전환. 호감은 `currentAffinity ≥ 70` 기준 권장.
- `turnOutcome`은 **enum**. 문자열 비교 금지.
- `reply`는 말풍선에 **스크롤 또는 '더 보기'** 처리 권장.

## 3. 판정 규칙 (코드가 강제)

### 3-1. 필드 정합성 (Sanitize)

| 규칙 | 처리 |
|---|---|
| `weaknessHit=false` → `hitWeaknessId=null` | 강제 |
| 존재하지 않는 약점/저항 id → null 처리 | 검증 |
| `resistanceTriggeredId=null` → 페널티 0 | 구조적 보장 |
| `codeRevealed=true`인데 `revealedValue` 비어 있음 → false로 강등 | 강등 |
| `codeRevealed`는 **턴 2 이상 + `weaknessHit=true`**일 때만 | 강제 |
| 🆕 **대질 전제 미충족 시 `codeRevealed` 무조건 false** | 강제 (측근 가드) |
| 이미 획득한 코드는 다시 true로 오지 않음 | 상태 관리 |
| LLM `suspicionDelta` 범위 **−10 ~ +20** | 클램프 |
| 🆕 LLM `affinityDelta` 범위 **−20 ~ +45** | 클램프 |
| `reply` 120자 초과 | 자름 (최후 안전장치) |

### 3-1-b. 🆕 집중력 (Focus) — 전투 자원

| 항목 | 값 |
|---|---|
| 턴당 집중력 | **3** |
| 카드 1장 비용 | 기본 1 (키워드 수 + 프레이밍 1) |
| 리셋 | **매 턴 시작 시 3으로 복구** |
| 초과 시 | 제출 차단 (`CanSubmit` false) |

> 카드별 개별 비용이 필요하면 `PlayerUtterance.FocusCost`에 UI가 직접 값을 넣는다.
> 미지정(0)이면 카드 수로 자동 계산된다.

### 3-2. 수치 계산 (Resolve) — **100 스케일**

| 규칙 | 값 |
|---|---|
| 매 턴 기본 의심 가산 | **+3** |
| 저항 발동 시 LLM delta **무시하고 페널티로 대체** | override (중복 가산 방지) |
| 턴당 의심 **증가** 상한 | **+30** (증가 턴에만 적용) |
| 🆕 감소 턴(무마) 계산 | `이전 + (LLM delta + 기본 +3)` — 상한 미적용, 0 하한 |
| 누적 의심 범위 | 0 ~ 100 |
| **발각 임계치** | **100** (= 즉시 작전 실패) |
| 🆕 친밀도 범위 | 0 ~ 100 (조직원별) |
| 🆕 `affinityMaxed` | `currentAffinity >= 100` |
| 누적 계산 전부 | **코드가 수행** (LLM 산수 신뢰 금지) |

### 3-3. 의심 증감 기준 (참고 — 밸런싱은 희석님)

| 상황 | 값 |
|---|---|
| 자연스러운 잡담·친밀 접근 | 0 ~ +3 |
| 매 턴 기본 (코드 가산) | +3 |
| 코드 근처 에둘러 접근 | +8 |
| 직설적 코드 요구 | +20 |
| 저항 발동 | `suspicionPenalty`로 **대체** |
| 3턴차 무마 성공 | −8 ~ −12 |

### 3-4. 🆕 친밀 증감 기준 (핵심 밸런싱)

| 상황 | 값 |
|---|---|
| `openingFrameIds` 적중 + 자연스러움 | **+35 ~ +45** |
| 무난한 대화 | +5 ~ +15 |
| 코드 압박(의심 상승 동반) | 0 ~ +20 |
| `betrayalFrameIds` 사용 | −10 ~ −20 |
| 발각성 발언 | −20 |

> **목표 설계:** 1턴 친밀(+40) → 2턴 코드(+20) → 3턴 친밀(+40) = **100%**
> 완벽 플레이 시 코드와 친밀 둘 다, 2턴에 실패하면 3턴을 코드에 써서 친밀 포기.
> **3주차 플레이테스트로 반드시 검증할 것.**

### 3-5. 턴 종료 결과 (`turnOutcome`)

| 값 | 조건 | 처리 |
|---|---|---|
| `Continue` | 턴 남음 | 다음 턴 |
| `Success` | 코드 획득 후 3턴 종료 | 코드 확보. 다음 노드 |
| `FailedExposed` | 누적 의심 100 또는 `exposed=true` | **작전 실패 → 게임오버** |
| `FailedTimeout` | 3턴 소진·코드 미획득 | **게임오버 아님.** 재도전 가능(의심·친밀 유지) |

> 폴백(통신·파싱 오류) 시에도 마지막 턴이면 Continue로 새지 않도록 턴 정보로 판정. 오류는 플레이어 책임이 아니므로 의심·친밀 변동 없음.

### 3-6. 🆕 엔딩 분기 (런 종료 시)

`affinityMaxed=true`인 조직원 수로 결정한다. **보스는 항상 추격.**

| 친밀 100% 인원 | 엔딩 | 추격자 |
|---|---|---|
| 3명 | **A. 완전한 신뢰** | 보스만 |
| 2명 | **B. 두 친구** | 보스 + 1인 |
| 1명 | **C. 한 친구** | 보스 + 2인 |
| 0명 | **D. 외로운 잠입** | 보스 + 3인 |

## 4. 🆕 `RunState` — 런 전체 상태 (서윤 관리)

전투를 넘나드는 상태. 조직원별 친밀도·누적 의심·획득 코드를 보관한다.

```json
{
  "suspicion": 34,
  "enemyAffinity": { "member_a_rookie": 100, "member_b_keeper": 60 },
  "acquiredCodes": { "1": "K", "2": "7" },
  "hasBossRoomKey": false
}
```

| 필드 | 설명 |
|---|---|
| `suspicion` | 런 누적 의심도 0~100. 전투 간 유지 |
| `enemyAffinity` | 조직원 id → 친밀도(0~100). 전투 간 유지 |
| `acquiredCodes` | codeIndex → 값. 3개 모이면 보스방 입력 가능 |
| `hasBossRoomKey` | 측근 돌파 시 true |

## 5. 요청 사항 (마감)

| 대상 | 할 일 | 기한 |
|---|---|---|
| **희석** | §0 프레이밍 ID 목록 확정 | 1주차 |

| **윤지** | 💣 의심 / ♥ 친밀 게이지 UI (둘 다 0~100%) | 1주차 |
